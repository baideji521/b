## 幻觉指标：旧算法已作废，新算法是分类判定

旧的 `hallucination_rate` 用 ground_truth 里的关键词做子串匹配，8 个组合全部得 1.0，
原因是像 "green leaves"（真值里就有的树叶）会命中 "leaves"（离开画面）这个标记词。
这个指标当时没有任何区分度，属于不可信指标。

现在按**语义类别 + 字段 + 例外**判定，规则写在 `benchmark/ground_truth.json` 的
`contradictions` 里，每条都带 `why`（为什么这是幻觉）和 `unless`（哪些写法不算）：

- `locomotion`：说有人走动/起身/进出画面 —— 真值是两人全程并排坐着
- `shot_change`：说镜头切换 —— 真值 scene_cuts 为空
- `wrong_place` / `wrong_object` / `extra_person`：地点、物体、人数与真值冲突

判定结果会带 evidence（命中的原句 + 类别），可以逐条复核。
复核后：4B / 2B / 4.5-int4 / 4.6 全部 0.000；用一段人工构造的"有人起身走出画面 +
镜头切到室外"的假输出验证，得 0.667，指标有区分度。

## OCR：不是主线，四个模型都读错

真值里屏幕上的文字是 `Pascall` / `Clinkers`（包装袋品牌）。实测：

- OCR 召回率（读对品牌词）：**四个模型、两种配置，全部 0.000**
- OCR 精确率（报告的文字里有多少是真的）：4B 配置A 0.000，编造样本 `candy` / `corn` / `cunner`
- 提高分辨率也读不对：480×640 读成 `Creme Egg`，576×768 读成 `CANDY CHOCOLATE` / `Creme Eggs`，
  800×1088 读成 `pascale's crunchers` / `pascale clinkers`（最接近但仍然错）

结论：这套 VLM 在 3060 能承受的分辨率下**不能当 OCR 用**。`ocr_text` 字段保留（它对
"画面里有包装/字幕"这个判断仍有价值），但不参与最终模型打分，也不做专门优化。
需要准确文字时应该接专门的 OCR 引擎，不在本轮范围内。

## 2B 慢的根因（原报告"加载 158.7s / 推理 474.2s / 只认出 1 人"不可复现）

重测：加载 5.0s（不是 158.7s），配置 A 视觉 96.8s，配置 C 49.3s，人数在配置 A 下是 2（不是 1）。
原数字大概率来自一次带首次编译/下载的冷跑，已作废。

真实原因是**输出长度**，不是单 token 速度：

- 2B 解码吞吐 16.9 tok/s，比 4B 的 11.8~12.5 tok/s **更快**
- 但 2B 在配置 A 平均生成 1522 token，4B 只生成 430 token（3.5 倍）
- 所以 2B 反而慢一倍：96.8s vs 43.4s

配置 C（max_new_tokens=192）把 2B 压到 49.3s，但代价是质量塌了：
人数众数变成 1（真值 2），覆盖率 0.565，重复率 0.125，事件被切成 8 条碎片。

结论：**2B 不是"因为小所以慢"，而是话多；压短了就不准。**
它仍然是有效的低显存备选（峰值 4.7GB），但不是默认。

## Tracking OFF / ON：实测后不采纳

做法：torchvision Faster R-CNN MobileNetV3-320（BSD-3，torchvision 已在依赖里，不引入新依赖）
+ ByteTrack 式两阶段 IoU 关联，只把"这一窗口有几个人"作为提示词提示注入，时间戳仍然只来自真实帧。

最终 4B 配置（batch=4）上的 A/B：

- tracking=off：视觉 30.0s，generate 25.9s，峰值 9650MB，事件 4，人数 2/一致性 1.0，覆盖 0.999，幻觉 0.0
- tracking=on ：视觉 19.7s，generate 13.1s，峰值 9634MB，事件 3，人数 2/一致性 1.0，覆盖 0.999，幻觉 0.0

不采纳，原因：

1. **没有收益**：4B 在全部 18 次实测里人数众数都是 2、一致性都是 1.0，本来就没错，没有可修的问题。
2. **有害**：开启后模型把提示词回吐进了事件名（`short phrase(<=8 words)`），事件命名质量下降。
3. 变快只是因为输出变短（generate 25.9s → 13.1s），不是理解变好。

按执行口令"如果提升不明显：不要加入主 Pipeline"，检测/跟踪代码已从仓库删除
（`src/vidscribe/visual/person_track.py` 已删，`visual.tracking` 配置项已移除）。
